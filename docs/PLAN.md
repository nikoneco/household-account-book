# 家計簿PWA 初期実装方針

2026-10-05。主に妻が利用し、夫も編集可能。日本円整数、日本時間、暦月、カード1枚。初回公開・GAS反映・専用表初期化は承認を受け実施済み。定期実行は未登録。

## 最小構成と完了条件

- ホーム、登録、履歴、毎月の設定。スマホの支出登録は主要項目と保存を先に表示する。
- 通常購入は9分類。ホームの出費内訳は食費・酒・外食・趣味・被服費・美容・必要経費・積立・固定費・その他の順。毎月の項目の分類は種別で決まり、積立は積立、固定費は固定費。既存の分類を一括書換えせず、固定費属性から内訳を表示する。
- 毎月の設定の一覧・月額の合計は積立を先に表示する。開いた出費内訳・積立残高は見出しと明細の背景色、交互の行色、区切り線で読みやすくする。内訳の開閉は端末内の読込済みデータだけで処理する。
- カードは27日締め、翌月28日請求。購入日と計上月を分け、計上月の手修正に対応。
- 支出は購入明細のみ。固定費実績も同じ明細。確定請求額は照合用で支出に加算しない。
- 設定を月別計画にコピーして固定。設定変更・停止で既存月を変えず、過去月に未作成の予定を後から自動生成しない。
- 積立残高は開始残高＋入金－取り崩し。購入とのリンクを検証し、取り崩しは資金移動。
- 積立で賄うカード購入は購入時に積立を指定、請求月に実際の支払いを確認して取り崩しを登録。指定だけでは残高を減らさない。
- 余り金は翌月へ持ち越さない。目的別積立残高だけは累積する。
- 今月の残りは給与からの購入・支払いと積立入金を差し引く。購入にひも付く取り崩し分をその購入の計上月の給与支出から除外。ひも付かない取り崩しは収入にしない。積立は予定・入金・取り崩し・残金の4項目。積立後差引・予定確保後の残りは表示しない。銀行口座残高と称さない。
- レシートは印字された購入日で登録。撮影・アップロード・解析日時の代用を禁止。不明なら要確認。
- 履歴は購入日・店名でレシート1件にまとめ、商品ごとの分類・数量・合計金額を開いて確認・修正する。数量で金額を再度掛けない。交通系マネーは現金扱い。
- レシート画面は画像保存、処理状況、元画像確認。利用者のJSON取込操作は撤去。
- ChatGPTが解析結果をSheetsの専用受取表へ直接追記。家計簿が編集アカウントで読み込まれる際に検証して反映。混在分類、合計、再試行、手修正保護を検証。
- Googleログインをサーバー側で検証。HOUSEHOLD_ALLOWED_EMAILのカンマ区切り許可メールに登録された家族は入力・編集可能。許可外・匿名を拒否。個人データをSWに保存しない。
- 境界・重複・整合・修正・認証拒否の自動テスト、ローカル画面操作、独立レビュー。

## 構成

外部パッケージに依存しないHTML/CSS/JavaScript PWAとGAS、非公開Sheets/Drive。共有計算をPWAとGASで使う。OAuthコード交換と短期セッションをサーバー側で管理する。HtmlService iframeの通信ブリッジでgoogle.script.runとpostMessageを使用。認証情報はURL・公開コードへ置かない。

解析結果の受取表はHB_ReceiptInbox。ChatGPTがA:Bへ追記し、GASがC:Dの処理状態を管理する。家計明細・処理状態を1回の原子的更新にまとめる。定期トリガーは作らず、まずアプリ読込時の反映を実装する。
